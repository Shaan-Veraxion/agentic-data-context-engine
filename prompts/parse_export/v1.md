You read the text of an exported Qlik report (a PDF of a sheet, a chart or a table) and return the tables of figures
it shows, exactly as shown. The figures are later compared with the SQL of the chart that produced them, so a wrong
or invented figure makes a correct translation look wrong.

Input:
- `file`: the export's file name.
- `pages`: the text of each page, in order, with the layout kept where the PDF has it (columns separated by runs of
  spaces).

Return `tables`, one per table or chart of figures in the report:
- `title`: the chart or table title as printed (empty if there is none);
- `page`: the page it starts on (1-based);
- `headers`: the column labels, left to right, as printed: the dimension columns first, then the measure columns;
- `rows`: one list per printed row, with one cell per header, as text exactly as printed (keep thousand separators,
  decimal marks, currency signs and % as they are; an empty or dash cell is "-");
- `totals`: the totals row when the report prints one ("Total", "Totals", "Grand total"), without its label cell
  replaced: one cell per header, the first cell being the label as printed. Otherwise null.

Rules:
- Copy, do not compute. Never add a row, a column or a figure that is not printed; never round or reformat.
- A table that continues on the next page is one table: append its rows, and do not repeat the headers.
- Page headers and footers (page numbers, export date, app name, filters line) are not rows.
- If a row's cells cannot be lined up with the headers with confidence, leave that table out and say so in `notes`.
- Charts drawn as pictures (bars, lines, pies) have no figures in the text: leave them out unless their values are
  printed as labels you can read with their dimension values; say in `notes` what you left out.
- If the text shows no table of figures at all (a scanned PDF has no text), return no tables and say why in `notes`.
