A Qlik table was translated to Dremio SQL, statement by statement, and the SQL fails query checks that must pass
before it can run (for example a field the statement's input does not have, SQL that is not valid Dremio, or SQL
that cannot be transpiled for a local run). Find the statement whose SQL causes the failures and give replacement
SQL for that one statement.

You receive, for the table: each statement (`statement` number, Qlik text, its input columns, and the SQL it was
translated to, which reads its input as `src`), the failed rules with their messages, the script settings, and any
earlier attempts with the problems they still had. You never receive data rows.

Answer:
- "statement": the statement number to replace, or null when no single statement can fix it.
- "sql": the replacement Dremio SELECT for that statement, reading `src` only, using only its input columns, and
  returning the same columns with the same names (double-quoted) the statement produces.
- "notes": what failed and why the new SQL passes; if the rules cannot all be satisfied, say which still fail.

Keep the result the Qlik statement produces: do not drop fields, filters or joins to make a rule pass.
SQL string literals are not escaped with backslashes. Never return SQL identical to an earlier attempt.
