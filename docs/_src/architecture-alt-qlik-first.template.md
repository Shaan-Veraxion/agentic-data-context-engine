## 4. Architecture decisions (ADRs)

### 4.1 Path decisions (ADR-Q1 to ADR-Q8)

#### ADR-Q1: Qlik & Reverse-SQL first
**Context.** The parallel plan builds all groups at once and reaches a first Reverse-SQL end-to-end at M2. The headline claim, the available inputs (Qlik scripts) and the most deterministic method (translation) all point at starting with Qlik.

**Decision.**
1. The first deliverable is **Reverse-SQL Mode A1**: Qlik scripts → BI IR → Dremio SQL, executed and validated (ADR-Q2).
2. Only the platform pieces this needs are built in Q0–Q1, each as a **lean version behind the final interface** (ADR-Q5).
3. Squads not on the critical path work on path-relevant pieces of their own agents (section 7.1), such as grain checks, lineage and the migration pack. They start their full scope at P1 (week 6).
4. **Mode B** (inference from outputs) starts at P3, once the KG holds keys and joins.

**Consequences.**
- The headline is proven by Q2 (week 8) with real client apps.
- The full platform completes around week 18 instead of week 12.
- Early KG content is dominated by BI-derived facts (documented trust), which is acceptable because ADR-3 trust rules apply unchanged.

**Alternatives considered.**
- (a) The parallel plan in `architecture.md`: faster to full scope, slower to proof.
- (b) Qlik-only with the other squads idle until week 6: wastes capacity. Rejected in favour of section 7.1.

#### ADR-Q2: The validation ladder: ground truth without Qlik server access
**Decision.** Every translated table and figure is labelled with the **highest level it reaches**. No result is called correct without a level.

| Level | Check | Ground truth | Comparison rule |
|---|---|---|---|
| **V0 Parsed** | Every statement in BI IR; nothing silently skipped | Script text | 100% of statements accounted for (`untranslated` counted) |
| **V1 Checked** | SQL parses in the Dremio dialect; passes Query-checker rules | KG + rules | No rule violation |
| **V2 Executes** | Runs in Dremio within budget; expected columns and types | Dremio | Schema equal to the BI IR table definition |
| **V3 Row-count parity** | Rows per Qlik table | Reload log "N Lines fetched"; QVD `NoOfRecords` | Exact, or within the drift tolerance when not time-aligned |
| **V4 Data parity** | Per column: distinct count, null count, min/max, sum (numeric); hash of sorted key sample | QVD contents | Exact on aligned snapshots; tolerance otherwise; every mismatch keeps a diff |
| **V5 Figure parity** | Report figures per visual and dimension member | Exported reports or owner-provided figures | Exact, or within the report's display rounding |
| **V6 Engine parity** (Mode A2) | `GetHyperCubeData` across ≥3 selection slices | Qlik engine | As in ADR-11 |

**Time alignment.**
- Dremio sources that are **Iceberg** are queried `AT TIMESTAMP <reload_time>`, so comparisons are exact.
- Otherwise a **drift tolerance** applies (default: relative row-count difference ≤ 0.5% and aggregate difference ≤ 0.5%, tunable per dataset). The snapshot gap is recorded as the reason.
- Drift is reported as `within tolerance (drift)` and never as `exact`.

**Consequences.** Results are honest and comparable across apps. The levels reachable depend on what the client provides (Q-12, Q-33, Q-34), which the gold set records per app.

#### ADR-Q3: Qlik script processing
**Decision.**
1. **Statement splitter first.** It must handle:
   - `//`, `/* */` and `REM` comments
   - strings and bracketed names containing `;`
   - `SUB … END SUB`, `IF/ELSEIF/ELSE/END IF`, `FOR/NEXT`, `FOR EACH`, `DO/LOOP`
   - `$(Include=…)` / `$(Must_Include=…)`, which are inlined, with spans pointing to the original file
2. **Lark grammar** for statements and expressions, grown from real scripts. Any statement the grammar cannot parse becomes `kind: other` with its raw text and span. **Nothing is dropped.**
3. **Variable resolution order:**
   1. values recorded in the reload log (as executed)
   2. `LET`/`SET` evaluated statically where deterministic
   3. Seed values from a reviewer

   Anything still unresolved goes to **Ask**, and dependent statements are marked `blocked`.
4. **Control flow.**
   - Loops with static bounds are unrolled.
   - Loops over file lists or data are resolved from the reload log where it shows the iterations.
   - Otherwise they are tier **T3** and reported.
5. **Coverage is a first-class metric** from Q0: statements parsed, statements translated, `kind: other` rate per app.

#### ADR-Q4: Source resolution and QVD chains
**Decision.**
1. **Connection mapping table.** Every Qlik data connection (`LIB CONNECT TO`, `ODBC/OLEDB CONNECT`, folder `lib://` paths) maps to a Dremio source or space, or to an original system. It is built from the scripts in Q0 and confirmed by a data owner (Seed mode, Q-35).
2. **Resolution order** for each `FROM` target:
   1. exact Dremio path through the mapping
   2. Dremio view definitions that wrap the original table
   3. name + schema match (Entity linker lite)
   4. data fingerprint match (ADR-16 L3/L4, from Q3)

   Every resolution is a `scope_link` fact with evidence. Anything below high confidence goes to **Queue**.
3. **QVD chains.**
   - Each QVD is a `:Dataset {kind: qvd}`.
   - A producing app is found from `STORE` statements and the QVD header `CreatorDoc`.
   - A consuming app is linked through `LOAD … FROM *.qvd`.
   - Translated SQL for a consumer **inlines the producer's CTE chain**, so the final SQL reads only Dremio datasets.
   - If a producer's script is missing, the result is `not resolved`, with the missing app named.
4. **Reproduce what Qlik reads.** If Qlik reads a duplicate or non-golden copy, the SQL reads that copy too. The golden equivalent is only flagged (ADR-16).

#### ADR-Q5: Lean first, same interface
**Decision.** Early pieces have fewer features, never a different interface.

| Piece | Lean now (Q0–Q1) | Full later | Contract |
|---|---|---|---|
| Repo, CI, config schema, Compose | Monorepo, `uv`, CI (lint/type/test/contract), config validated at startup; profiles `core`, `dremio-local`, `bi-fixtures`, `obs` | All profiles, Helm, signed images | ADR-15 |
| `data_port` | `DremioSource` (Flight SQL, catalog API, view definitions, Iceberg time travel), `FileSource` | Query history, equivalence fingerprints | ADR-13 |
| KG | `kg_port` over the **`fact_log`** in Postgres + outbox | Brahmastra `kg-engine` projection (Q2), search, resolution | ADR-12 |
| `model-gateway` | Vertex adapter (Claude), structured outputs, caching, memoization, record/replay, budgets, **no-row-data policy** (ADR-Q6) | Gemini, other providers, Presidio | ADR-7, ADR-14 |
| HITL | `hitl-service` with Ask, Queue, Gate | Seed/Correct UX, impact ranking | ADR-5 |
| Workbench | 3 screens (section 6.2) | Full workbench | ADR-9 |
| Orchestration | LangGraph subgraph for the Qlik pipeline; events via the Postgres outbox | Redis Streams, all subgraphs | ADR-6 |
| Eval | BI gold set + harness | All gold sets | ADR-10 |

**Fact log first.** The `fact_log` is the target system of record (ADR-12), so building it first is not throwaway. Sketch:

```sql
CREATE TABLE fact_log (
  fact_id        uuid        NOT NULL,
  version        int         NOT NULL,
  tenant_id      text        NOT NULL,
  scope_id       text        NOT NULL,
  kind           text        NOT NULL,          -- bi_transform, bi_model_link, report_sql, scope_link, ...
  subject_ref    text        NOT NULL,          -- canonical entity id (app/table/visual/dataset/column)
  payload        jsonb       NOT NULL,          -- validated against the fact-kind schema
  trust          text        NOT NULL,          -- confirmed | documented | validated | inferred
  confidence     numeric,
  impact         int,
  valid_from     timestamptz, valid_to timestamptz,               -- when true in the data
  recorded_at    timestamptz NOT NULL DEFAULT now(),
  invalidated_at timestamptz,                                       -- when we stopped believing it
  supersedes     uuid,
  evidence       jsonb       NOT NULL,          -- [{kind: bi_script|qvd_header|reload_log|dq_check|..., ref}]
  produced_by    text        NOT NULL,          -- agent@version
  prompt_version text, model text, run_id uuid,
  PRIMARY KEY (fact_id, version)
);
-- insert-only: the application role has INSERT and SELECT, never UPDATE or DELETE.
-- invalidation = a new version row with invalidated_at set.
CREATE TABLE outbox (id bigserial PRIMARY KEY, fact_id uuid, version int, event text, payload jsonb,
                     created_at timestamptz DEFAULT now(), published_at timestamptz);
```

#### ADR-Q6: No row-level data reaches any LLM on this path
**Decision.**
- **LLMs on this path may see:**
  - script text and BI IR
  - Dremio schemas and view definitions
  - aggregate diffs from reconciliation (counts, sums, distinct counts per dimension member)
  - exported report layouts
- **They never see** QVD rows, Dremio rows or sample values.
- `model-gateway` enforces this with a payload classifier that rejects row-shaped data from path routes. Presidio masking (ADR-8) is added when sample-based agents arrive in P1.

**Consequences.** The privacy boundary holds from day 1 without waiting for masking. Report-export PDFs may contain figures: those are aggregates and allowed.

#### ADR-Q7: The migration pack is the path's deliverable
**Decision.** For each Qlik app, `dictionary publisher (20-lite)` exports one versioned folder:

```
<app-name>__<reload_time>__pack-v<N>/
  manifest.json            app id, inputs received (scripts, logs, QVDs, exports), tool and model versions, run id
  sql/
    tables/<qlik_table>.sql        Dremio SQL per Qlik table (CTE chain, QVD producers inlined)
    measures/<measure_id>.sql      per master measure / visual measure (where definitions exist)
  lineage/
    lineage.json            nodes and edges: Dremio datasets → Qlik tables → QVDs → apps → visuals (OpenLineage-compatible)
    lineage.md              readable summary with the QVD chain
  validation/
    report.md / report.xlsx  ladder level per table and figure, diffs, tolerances, drift reasons
  review/
    untranslated.csv        statements flagged untranslated, with spans
    decisions.csv           reviewer decisions applied (Ask / Queue / Gate)
    open-items.md           anything not resolved, e.g. a missing producer app
```

The pack is reproducible: the same inputs and versions regenerate it identically (memoized LLM routes, ADR-7).

#### ADR-Q8: Reconciliation execution in Dremio
**Decision.**
1. Each comparison is a **bounded pushdown query** (count, aggregates, grouped aggregates), never a full extract. Only small result sets come back.
2. **Results are cached** by (SQL fingerprint, dataset versions, snapshot), so re-runs cost nothing until inputs change.
3. Grouped comparisons pinpoint mismatches by dimension member. The Diagnoser (Opus, aggregate diffs only) proposes causes: filter, join fan-out, NULL handling, date logic, missing producer.
4. Load limits and labels as in ADR-13; reconciliation batches run off-peak on the client's Dremio.

## 9. Risks

### 9.1 Risks specific to this path

| Risk | Mitigation |
|---|---|
| **Qlik syntax long tail** breaks the parser | Grammar grown from real scripts, statement-level fallback to `kind: other` + LLM, coverage tracked per app from Q0 (ADR-Q3) |
| **No measure definitions provided** (scripts only) | The table-level ladder (V0–V4) still delivers lineage and SQL. Visual-level work waits for `-prj` or app files (Q-07). |
| **Data drift since reload** makes parity look wrong | Iceberg time travel where possible (Q-36); otherwise drift tolerance with the snapshot gap recorded (ADR-Q2) |
| **Qlik Cloud reload logs are summaries**, missing per-table "Lines fetched" | Client-managed script logs where available; QVD headers (V3) and QVD data (V4) as the fallback (Q-34) |
| **Qlik reads sources not in Dremio**, or duplicate copies | Connection mapping (Seed), lite linker, equivalence L1/L3 in Q3 (ADR-Q4, Q-11) |
| **Producer apps missing** from a QVD chain | `not resolved` with the missing app named; request list in the migration pack's `open-items.md` |
| **Lean KG now causes rework later** | The fact log is the target system of record; `kg_port` keeps callers stable; the Neo4j projection is additive (ADR-Q5) |
| **Load on the client's Dremio** from reconciliation | Bounded pushdown, result caching, off-peak batches, load limits (ADR-Q8, Q-10) |
| **Full platform arrives later** (around week 18) | Accepted trade-off (ADR-Q1); P-phases start in week 6 so non-path squads are never idle |
